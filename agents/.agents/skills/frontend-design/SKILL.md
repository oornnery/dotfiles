# Frontend design

Use when visual/UI quality is part of success, not merely code correctness.

## References

- Visual system and component language: `references/visual-system.md`
- Incremental frontend refactoring: `references/refactoring.md`
- Accessibility and interaction states: `references/accessibility.md`

## Principles

- Start from product, content, audience, and existing identity.
- Strong hierarchy beats decorative density.
- Reuse tokens/components but do not force every surface into a card.
- Prefer fewer, clearer regions over nested panels.
- Typography, spacing, alignment, and state clarity carry most quality.
- Avoid generic AI output: excessive gradients, glass, huge rounded cards, random
  badges, dashboard grids, fake metrics, decorative blobs, and meaningless motion.
- Responsive behavior is designed, not a final media-query patch.
- Render and inspect; code review alone cannot prove visual quality.
