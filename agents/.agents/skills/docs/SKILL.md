# Documentation

Identify audience, task, prerequisites, expected result, and source of truth. Verify
commands, paths, flags, APIs, defaults, and limitations against code/config.

Prefer:

- runnable minimal example;
- progressive detail;
- explicit prerequisites and failure recovery;
- exact version-sensitive notes;
- links/paths to source of truth;
- concise status and known limits.

Do not invent support, performance, output, test results, or roadmap promises.
